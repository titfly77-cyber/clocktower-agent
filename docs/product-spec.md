# 产品规格 v0.1

状态：可用于开发拆解；未实现、未通过实桌验证。

## 1. 产品目标与输入

为血染钟楼说书人提供当前流程状态、现场氛围、阶段总结和局后复盘。

现有输入是玩家与 DM 的混合音频，以及 App 的切换阶段、调整氛围事件。不能预设系统有独立 DM 音轨、摄像头、棋子识别、举手识别或可靠的玩家座位映射。

App 的确认状态、声音中的说法、模型推断和局后揭晓分别保存来源。首版以 DM 为主要使用者。

## 2. 八个流程状态

这些是产品状态，不是对官方规则阶段数量的重新定义。

| 编码 | 名称 | 主要记录与处理 |
| --- | --- | --- |
| SETUP | 开局准备 | 开始本局；可补充剧本与参与者；记录规则说明。 |
| NIGHT | 夜晚行动 | 记录夜晚序号及起止；不从脚步、衣物声或含混对话推断角色行动。 |
| DAWN | 黎明公布 | 整理 DM 宣布的死亡和其他公开结果，待 DM 核对。 |
| DISCUSSION | 白天交流 | 整理发言、信息交换和推理；此状态不代表所有收音都是公开发言。 |
| NOMINATION | 提名辩论 | 记录提名与辩护相关说法；具体提名成立与双方身份需明确证据。 |
| VOTING | 投票进行 | 记录投票时段与明确宣布的结果；没有票数记录时留空。 |
| DAY_END | 日末结算 | 整理本日结果、处决及死亡信息；触发当日总结草稿。 |
| POSTGAME | 终局复盘 | 接收 DM 宣布的终局结果和揭晓信息；生成局后复盘。 |

### 2.1 正常流转

- 开局：SETUP → NIGHT → DAWN → DISCUSSION。
- 日间：DISCUSSION → NOMINATION → VOTING。
- 投票后：可回 DISCUSSION、进入新一轮 NOMINATION，或由 DM 转入 DAY_END。
- 未发生提名或投票时，也可由 DM 从 DISCUSSION 转入 DAY_END。
- 日末：DAY_END → NIGHT → DAWN，进入下一天。
- 任何进行中的状态都可由 DM 切换至 POSTGAME；不根据存活人数自动宣布胜负。

提名与投票允许一天内重复。投票完成不自动等于处决；处决和死亡分别记录，不自动互相推导。特殊角色、剧本或场内流程由 DM 修正状态，不通过硬编码流程否定 DM 操作。

### 2.2 轮次

- 准备阶段：day=0，night=0。
- 首夜：day=0，night=1。
- 首次黎明至当日日末：day=1，night=1。
- 此后入夜：保留上一白天的 day，night 增加；黎明再令 day 与 night 对齐。
- 修正和撤销必须同时恢复阶段与轮次，不因重入某个界面额外增加轮次。

### 2.3 切换阶段按钮

首页显示当前状态与轮次，例如“第 2 天 · 提名辩论”。点击“切换阶段”展开八个状态，突出当前流程下的常用下一步。

- 推荐下一步只影响显示顺序，不限制 DM 手动选择。
- DM 点击后立即生效，记录来源、时间和新的状态修订号。
- 提供“撤销上次切换”和轮次修正；保留原记录及修正关系。
- 语音识别结果显示为“建议切换”，点击采纳后才成为正式状态。
- 新的手动切换使旧状态下产生的待确认建议失效。
- 同一按钮事件重传不重复切换、不重复增加轮次。

## 3. 八种现场氛围

| 编码 | 标签 | 支持判断的互动信号 | 需要避免的混淆 |
| --- | --- | --- | --- |
| RELAXED | 轻松社交 | 自然闲聊、调侃、交流从容。 | 普通背景人声不代表全桌轻松。 |
| FOCUSED | 专注推理 | 持续核对信息、比较说法、讨论技能关系。 | 安静思考不等于参与低迷。 |
| CONTENTIOUS | 激烈交锋 | 游戏内质疑、辩护、拉票和反驳密集。 | 游戏内对抗不等于现实交流摩擦。 |
| TENSE | 紧张悬念 | 关注集中于关键选择或即将公布的结果。 | 不能只因进入投票阶段就判定紧张。 |
| EXCITED | 欢乐兴奋 | 笑声、欢呼、惊讶等集中出现。 | 短暂单人笑声不代表全桌持续兴奋。 |
| CONFUSED | 困惑停滞 | 反复要求解释或复述，理解困难阻碍推进。 | 说法存在矛盾是正常游戏现象，不自动等于困惑。 |
| DISENGAGED | 参与低迷 | 交流时段持续缺少回应，多次引导仍难以推进。 | 夜晚、规则讲解、思考、离开收音范围都不能单独支持此标签。 |
| FRICTION | 交流摩擦 | 持续打断、表达不满，交流方式影响正常游戏。 | 不根据音量大、脏话或单次反驳直接定性；提示 DM 判断。 |

这是本产品的分类提案，并非经过验证的心理量表。标签描述被设备捕获到的互动，不能证明玩家的真实情绪、诚实程度或阵营。

### 3.1 自动输出

- 主氛围：八选一，证据不足时为空。
- 次氛围：可选，与主氛围不同；证据不足时不输出。
- 强度：低、中、高；与识别置信度分开。
- 置信度：低、中、高；不显示未经校准的精确概率。
- 判断依据：短句及对应音频时间范围。
- 观察状态：有效、证据不足或已过期。
- 来源：Agent 估计或 DM 标记。

“暂不判断”不是第九种氛围。收音不足时保留上次记录的时间，但不把旧标签呈现为当前新判断。标签变化须参考连续上下文，分析窗口和切换阈值待实桌录音校准。

### 3.2 调整氛围按钮

点击“调整氛围”展示八张标签卡和低／中／高三档强度。首版手动操作只要求一个主标签。

- 默认处于自动模式。
- DM 选择标签和强度后进入手动模式；不为人工标签附加模型置信度。
- 手动选择保留到 DM 点击“恢复自动”，阶段切换也不自动解除。
- 锁定期间可以继续保存模型估计，但不覆盖界面上的有效人工标签。
- 恢复自动后采用恢复操作之后产生、且针对当前状态的有效估计；在新结果到达前显示“正在判断”。
- 人工标记只作用于本局，不能未经复核就作为永久训练标签。

如果未来需要控制灯光或音乐，另外保存“希望营造的氛围”，与“识别到的现场氛围”分开；控制指令不直接改写观察结果。现阶段不假设硬件具备输出能力。

## 4. 混合音频的处理原则

1. 将音频、转写、按钮事件放到同一条本局时间线上，保留采集时间与接收时间。
2. 识别“开始提名”“现在投票”等表达时，结合现有阶段形成建议；引用、玩笑和 DM 身份不明都降低确定性。
3. 不预设模型能稳定区分 DM 与玩家。说话人分段与真实座位映射是不同任务；未确认时使用匿名标识或“发言者待确认”。
4. 发言提到某个座位，不代表发言者就是该座位；无法区分时不生成个人发言统计。
5. 重叠语音、缺失片段和不清晰转写要标记，不补写未听清的关键事实。
6. 夜晚的动作、实际举手名单及未说出的角色状态需要额外记录，声音不能完整还原。
7. 自动判定的流程建议、氛围和事实提取都应关联证据范围，方便 DM 修正。

## 5. 阶段总结与局后复盘

### 5.1 当日总结

进入 DAY_END 时生成草稿，默认仅展示给 DM。内容包括：

- 当日已确认的公开事件。
- 各方声称的信息及主要讨论脉络；“玩家声称”与“已确认事件”分开表述。
- 有记录的提名与投票结果；缺失内容直接标明缺失。
- 氛围变化、高光片段及对应时间。

进入其他阶段时更新记录；不在每次切换时自动向全桌播报。DM 可主动生成当前阶段总结。

### 5.2 公开信息边界

- 所有原始转写和自动提取默认仅供 DM 查看。
- 混合录音不能仅凭阶段或音量确定公聊、私聊；没有确认的记录不能直接加入面向玩家的总结。
- DM 确认某记录可公开，不代表确认该玩家说法是真实角色信息。
- 玩家版总结从已确认可公开的记录单独生成，不使用私密记录暗示身份或给出推理结论。
- 玩家版总结的展示或播报由 DM 明确触发，不由模型自行决定。

### 5.3 局后复盘

进入 POSTGAME 后生成过程回顾；DM 可以口述或录入揭晓内容，再完善真相解释。

- 过程层：讨论、提名、投票、公开结果及氛围高光。
- 揭晓层：DM 确认的身份、关键行动、状态及技能影响。
- 解释层：基于有记录的过程与揭晓信息，说明误判如何形成、决策如何影响局面。

没有真实身份和夜间信息时，只交付过程复盘；不推测隐藏行动。没有逐人投票记录时，不生成逐人投票画像。不将一次复盘上升为人格、诚实程度或稳定能力评价。

### 5.4 修正与版本

修正阶段、轮次或关键记录后，将受到影响的总结标记为需要更新。新版本保留来源范围和生成时间；已展示给玩家的旧版本保留历史，不能静默替换。

## 6. 首页信息布局

从上到下：

1. 本局名称、轮次、当前阶段、阶段来源。
2. “切换阶段”和“撤销上次切换”。
3. 当前氛围、强度、来源、更新时间及一条判断依据。
4. “调整氛围”和手动模式下的“恢复自动”。
5. 可采纳的阶段建议、待核对记录。
6. 本阶段记录与总结入口。

“待确认”和“证据不足”均为正常可见状态，不通过虚假的高置信度掩盖。

## 7. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 玩家模仿 DM 说“天黑了” | 最多出现候选建议，不直接改变正式阶段。 |
| DM 已切换阶段，旧音频分析迟到 | 不覆盖新阶段，过期建议不可采纳。 |
| 一天发生多次提名投票 | 轮次保持，分别记录，不在首轮投票后自动处决。 |
| 当天无人被处决 | 正常进入日末结算，不伪造处决。 |
| 处决后是否死亡不明 | 死亡状态留空，不由处决自动推导。 |
| 阶段误切换后撤销 | 阶段与轮次一起恢复，保留审计记录。 |
| 同一按键事件重传 | 只生效一次。 |
| DM 手动标记紧张，模型随后估计欢乐 | 有效显示保持 DM 标记。 |
| 手动模式下进入新阶段 | 人工标签仍保留，并持续显示来源和标记时间。 |
| 点击恢复自动 | 旧估计不立即冒充新结果，等待当前阶段的新估计。 |
| 夜晚安静或玩家走远私聊 | 不仅凭安静判为参与低迷。 |
| 听到“我昨天说三号可疑”但说话人不明 | 不把发言归到三号。 |
| 录入设备收到了私聊 | 默认仅供 DM 查看，不自动出现在玩家版总结。 |
| 缺少真实身份、夜间行动或逐人票型 | 对应复盘部分标记缺失，不编造。 |
| DM 修正总结依赖的记录 | 原总结提示需要更新，新版本保留修正依据。 |

## 8. 验证与未定事项

这些验收场景是后续实现的验证要求，本次仅检查文档和示例结构，不宣称识别能力已通过验证。

实桌验证需覆盖安静推理、多人重叠说话、私聊远离麦克风、连续提名和正常激烈辩论。分别评估阶段建议的准确性与延迟、关键信息漏记／错记、氛围标签的人类标注一致性，以及 DM 修正操作的负担。具体数值目标待录音样本与运行条件确定。

尚未确定 App 平台、音频格式及接入方式、模型提供方、部署方式、延迟与成本预算；不据此虚构已完成的技术架构。
